# ПЛАТФОРМА — защищённая синхронизация (проект, НЕ активирована)

Существующий адрес и интерфейс: https://groupmetadsp.github.io/

## Выявленное состояние
- Публикуемый каталог читается из `rubrics.json` (и устаревших `catalogs.json`, `tools.json`).
- Редактирование, скрытие и сортировка сохраняются в браузере в `platform-hierarchy-v2`, `platform-hierarchy-deleted-v1`, `platform-hierarchy-order-v1`.
- Поэтому локальные материалы разных компьютеров сейчас не синхронизируются.

## Безопасная архитектура
1. GitHub Pages продолжает отдавать те же HTML/CSS/JS по тому же адресу.
2. Отдельная активная БД хранит общий каталог (подразделы, материалы, статусы, порядок и удалённые элементы), журнал редакций и историю изменений.
3. Чтение и запись выполняются только после авторизации редактора. В публичном JS разрешён лишь publishable-ключ; secret/service-role ключи недопустимы.
4. Row Level Security ограничивает доступ списком членов команды; запись разрешена редакторам. Ревизия документа защищает от затирки чужих изменений.
5. Первая миграция: экспортировать локальные данные с КАЖДОГО компьютера, сохранить отдельные резервные копии, сравнить/объединить их с опубликованным rubrics.json и лишь затем загрузить объединённый каталог.
6. При ошибке сети не терять локальный черновик; новые правки оставлять в очереди до разрешения конфликта. Периодически обновлять и при необходимости использовать Realtime.
7. Оформление, звук, тема и другие личные настройки остаются локальными.
8. Выключать старую локальную модель только после проверки авторизации, RLS, работы на двух ПК и восстановления из истории.

## Что ещё требуется для активации
- Выбрать или создать выделенный активный проект базы данных. Единственный доступный Supabase-проект `PROEKTSET` сейчас INACTIVE; его нельзя незаметно переиспользовать для ПЛАТФОРМЫ.
- Настроить Auth, подтверждённых редакторов и RLS, применить и проверить схему `sync/schema.sql`.
- Написать/подключить клиентский адаптер для чтения и отправки изменений, с автоматической миграцией после резервного копирования и разрешения конфликтов.
- Провести тесты одновременно на двух разных компьютерах.
